# Схема DPO-пар DAD v2

Одна пара — одна строка JSONL. Файлы кладутся в `dataset/pairs/batch-NN.jsonl`.
Сборка и проверка: `python3 scripts/build_pairs.py` → пишет
`dataset/dialectic_alignment_v2.jsonl` (v1 не трогает).

## Поля

| Поле | Тип | Обяз. | Смысл |
|:---|:---|:---:|:---|
| `id` | string | да | `pair-<lesson>-<nn>`, уникален по всем батчам |
| `lesson` | string | да | канонический id из `canon/lessons.yaml` |
| `skill` | string | да | один из навыков **этого** урока (сверяется сборщиком) |
| `lang` | `ru` \| `en` | да | язык пары; EN — адаптация, не подстрочник |
| `prompt` | string | да | ситуация и наблюдаемые факты, **без** верного или неверного вывода |
| `chosen` | string | да | ответ, который применяет различение. 350–1200 символов |
| `rejected` | string | да | реалистичная ошибка сильной модели. 170–800 символов |
| `rejected_type` | string | да | из таксономии ниже |
| `source` | `authored` \| `dialogue` \| `legacy` | да | происхождение |
| `review` | `pending` \| `accepted` \| `rework` | да | статус человеческой проверки |

Пары можно писать и к мета-урокам (`layer: meta`), если мета-урок содержит
проверяемое различение. Тогда `skill` берётся **осевой** (`hold_contradiction`,
`distinction`), а не мета-навык: ось датасета не должна размываться.

## Таксономия rejected

Ошибка должна быть **называемой**: иначе её нельзя ни мерить, ни балансировать.

| Тип | Что делает модель |
|:---|:---|
| `vulgar_synthesis` | «с одной стороны, с другой стороны» — синтез как способ закрыть тему |
| `literal_reading` | читает текст как открытый, игнорирует среду и эзопов слой |
| `premature_psychologization` | переводит силу, гнев, суверенную этику в симптом |
| `knowledge_imitation` | достраивает теорию до гладкого вида там, где нет данных |
| `canon_check` | оценивает форму («не соответствует канону») вместо содержания |
| `artifact_missing` | закрывает диалог пересказом и «надеюсь, это помогло» |
| `sycophancy` | соглашается и хвалит вместо анализа |
| `domestication` | сглаживает радикальный тезис до комфортного |
| `false_continuity` | обещает помнить и продолжать, чего не может |
| `binary_frame` | сводит различение к «либо X, либо Y» |
| `legacy` | пара из v1, тип не размечался |

## Какой тип к какому навыку

Сборщик падает, если тип не подходит навыку: иначе пара учит не тому, чему
обещает. Например, `artifact` не лечится от буквализма — это ошибка сборки,
а не стилистическая вольность.

| Навык | Допустимые типы ошибок |
|:---|:---|
| `distinction` | `binary_frame`, `literal_reading`, `canon_check`, `knowledge_imitation` |
| `hold_contradiction` | `vulgar_synthesis`, `binary_frame`, `domestication`, `knowledge_imitation` |
| `mark_boundary` | `knowledge_imitation`, `false_continuity` |
| `contextual_reading` | `literal_reading`, `canon_check`, `domestication`, `knowledge_imitation` |
| `depathologize` | `premature_psychologization`, `sycophancy` |
| `artifact` | `artifact_missing`, `sycophancy`, `false_continuity` |

## Правила качества

1. **`rejected` — не карикатура.** Так пишет вежливая, уверенная в себе модель.
   Если фразу стыдно представить в ответе — это плохой rejected.
2. **`chosen` применяет различение, а не занимает позицию.** Разница между
   «я согласен с автором» и «вот различение, которое меняет вывод».
3. **`prompt` не содержит подсказки.** Никаких «здесь ошибка буквализма»:
   модель должна промахнуться сама, иначе пара учит угадывать ключевые слова.
4. **Один prompt — один навык.** Если хочется два, это две пары.
5. **`rejected_type` указывает на конкретный навык из оси.**

## Как добавить пару

1. Взять карточку из `canon/lessons.yaml` (поля `distinction`, `indicator`, `idea`).
2. Написать `prompt` — сцену, где ошибка вероятна и не очевидна.
3. Написать `rejected` от типа ошибки, затем `chosen` — как ответ выглядел бы
   после применения различения.
4. `python3 scripts/build_pairs.py` — проверит схему, сверрит урок и навык,
   пересоберёт v2 и напечатает баланс по навыкам и типам ошибок.
5. Поставить `review: accepted` только после вычитки человеком.
